CRIANDO UM NOVO CLIENTE NO NORIA / MAG.IA
==========================================

Objetivo deste documento
------------------------

Este arquivo e o passo a passo oficial para cadastrar um novo cliente
multi-tenant no sistema.

Ele cobre:

1. Criacao do usuario no Supabase Auth.
2. Criacao do tenant.
3. Vinculo do usuario ao tenant.
4. Configuracao de prompt e IA.
5. Configuracao do Kanban do cliente.
6. Cadastro do canal WhatsApp via Evolution API.
7. Configuracao do webhook na Evolution.
8. Checklist de teste.

Exemplo usado neste documento:

Cliente: Universo Prata
Slug: universo_prata
Canal inicial: WhatsApp
Objetivo: atendimento comercial para joias/prata, apresentacao de produtos,
conducao de venda e transferencia para humano quando necessario.


ANTES DE COMECAR
-----------------

Confirme que estas etapas ja foram feitas no ambiente:

1. Migration 015 ja rodada no Supabase:
   supabase/migrations/015_align_tenant_member_roles.sql

2. Workflow WhatsApp atualizado importado no n8n:
   n8n/workflows/magia_whatsapp_evolution_mvp.json

3. Workflow Command Router atualizado importado no n8n:
   n8n/workflows/magia_command_router.json

4. Workflow WhatsApp ativo no n8n.

5. URL publica do webhook WhatsApp disponivel:
   https://auton8n-n8n.tplv5d.easypanel.host/webhook/magia-whatsapp

6. Evolution API acessivel e com permissao para criar/conectar instancias.


PADRAO DE SLUG
--------------

Use sempre slug em minusculo, sem acento e com underline.

Exemplos corretos:

universo_prata
clinica_nubia
jiw

Evite:

Universo_Prata
universo prata
universo-prata
universoprata

O slug e usado para filtrar dados do cliente na interface e no n8n.


1. CRIAR USUARIO NO SUPABASE AUTH
---------------------------------

No Supabase:

Authentication > Users > Add user

Preencha:

- Email do dono/operador.
- Senha inicial.
- Confirm email: pode deixar confirmado para teste/onboarding.

Depois de criar, copie o email usado.
O SQL de membership usa esse email para encontrar o user_id em auth.users.

Exemplo:

email_owner@dominio.com


2. CRIAR TENANT, USUARIO, IA, KANBAN E CANAL WHATSAPP
-----------------------------------------------------

Rode o SQL abaixo no Supabase SQL Editor.

Antes de rodar, ajuste obrigatoriamente:

- AJUSTAR_EMAIL_OWNER
- AJUSTAR_INSTANCIA_EVOLUTION
- AJUSTAR_TELEFONE_WHATSAPP

Para o caso Universo Prata, sugestao:

- slug: universo_prata
- name: Universo Prata
- industry: Joias, prata e varejo
- instancia Evolution: universo_prata
- telefone: numero conectado na Evolution em formato internacional, so numeros

Formato do telefone:

55 + DDD + numero

Exemplo:

5521999999999

Voce e a assistente virtual de vendas da Universo Prata.

Seu objetivo e conversar com clientes de forma natural, entender o que estao
procurando, apresentar produtos compativeis e conduzir a conversa para uma
possivel compra.

Use portugues brasileiro e mensagens adequadas para WhatsApp.

Seja simpatica, objetiva e comercial, sem pressionar a cliente.

Evite textos muito grandes. Normalmente responda com 1 a 3 frases.

Faca apenas uma pergunta por vez sempre que possivel.

Nao transforme a conversa em um questionario.

Sempre considere tudo o que a cliente ja informou anteriormente.

PRODUTOS

Utilize somente produtos, precos, estoque, colecoes, links e informacoes
disponiveis na base fornecida pelo sistema ou na conversa.

Nunca invente:

- produto;
- preco;
- estoque;
- promocao;
- desconto;
- prazo;
- condicao de pagamento.

Caso nao tenha uma informacao, diga isso normalmente e encaminhe para uma
pessoa da equipe quando necessario.

ATENDIMENTO COMERCIAL

Quando a cliente explicar o que procura, apresente poucas opcoes relevantes.

Evite enviar muitas opcoes de uma vez.

Continue a conversa de acordo com a reacao da cliente.

Quando houver sinais claros de interesse em compra, conduza para o proximo
passo.

Exemplos de intencao forte:

- quero esse;
- gostei desse;
- como compro;
- tem disponivel;
- tem meu tamanho;
- me manda o link;
- quanto fica.

Nao transfira para humano apenas porque a cliente quer comprar.
Tente conduzir a venda sempre que possuir as informacoes necessarias.

KANBAN

Durante a conversa, identifique mentalmente em qual etapa o atendimento esta:

NOVO_CONTATO:
quando ainda nao souber o que a cliente procura.

INTERESSE_IDENTIFICADO:
quando entender o tipo de produto ou necessidade.

PRODUTOS_APRESENTADOS:
quando ja tiver apresentado produtos.

INTERESSE_COMPRA:
quando a cliente demonstrar intencao real de comprar.

AGUARDANDO_FINALIZACAO:
quando a cliente ja tiver escolhido e estiver finalizando a compra.

VENDA_CONCLUIDA:
somente quando houver confirmacao real de venda concluida.

AGUARDANDO_HUMANO:
quando a cliente pedir atendente, houver reclamacao, problema de pagamento,
negociacao especial, falta de informacao ou situacao fora das regras.

ATENDIMENTO HUMANO

Use atendimento humano quando:

- a cliente pedir uma pessoa;
- voce nao tiver informacao suficiente;
- houver problema;
- houver reclamacao;
- houver negociacao especial;
- houver situacao fora das regras cadastradas.

Quando precisar transferir, responda de forma natural e inclua a tag interna:
[HUMANO_SOLICITADO]

FORMATO

- Nao diga que e inteligencia artificial.
- Nao explique o funcionamento interno do sistema.
- Nao exponha tags tecnicas para a cliente.
- Nao use Markdown.
- Para listas, use bullets simples apenas quando necessario.
- Responda somente com a mensagem que deve ser enviada ao cliente.

3. CONFIGURAR A INSTANCIA NO EVOLUTION API
------------------------------------------

Na Evolution API:

1. Crie uma nova instancia para o cliente.
2. Use como nome da instancia o mesmo valor cadastrado em channels.external_id.
3. Exemplo recomendado:

   universo_prata

4. Conecte o WhatsApp escaneando o QR Code.
5. Confirme que a instancia esta como conectada/open.

Atencao:

O nome da instancia precisa bater com o Supabase.
O workflow WhatsApp resolve o tenant comparando a instancia recebida da Evolution
com:

- channels.external_id
- channels.config.instance_name
- channels.config.instance
- channels.config.evolution_instance

Se isso nao bater, o workflow pode cair no tenant fallback.


4. CONFIGURAR WEBHOOK DO WHATSAPP NA EVOLUTION
----------------------------------------------

Configure o webhook da instancia na Evolution com:

https://auton8n-n8n.tplv5d.easypanel.host/webhook/magia-whatsapp

Evento principal:

MESSAGES_UPSERT

Para o teste inicial, ative somente esse evento.

Nao coloque tenant_slug na URL do WhatsApp.
No WhatsApp, o tenant deve ser resolvido pela instancia recebida da Evolution.


5. CONFIGURACOES DO N8N / EASYPANEL
-----------------------------------

O fluxo WhatsApp atual depende das credenciais globais dos nodes ativos:

- Supabase
- Redis
- Gemini
- Evolution API

Para WhatsApp, normalmente nao e necessario criar uma variavel por cliente
com token, porque a Evolution centraliza as instancias.

O ponto essencial por cliente e:

- instancia criada na Evolution;
- instancia cadastrada em public.channels;
- webhook apontando para /webhook/magia-whatsapp.

Se o ambiente ainda usa fallback, confira se existe:

WHATSAPP_TENANT_SLUG
DEFAULT_TENANT_SLUG

Essas variaveis so devem ser fallback.
Elas nao devem ser a forma principal de identificar clientes com WhatsApp.


6. CHECKLIST DE TESTE DO NOVO CLIENTE
-------------------------------------

Depois de rodar o SQL e configurar a Evolution:

1. Entre na interface com o usuario criado no Supabase Auth.
2. Confirme que o usuario enxerga somente o tenant Universo Prata.
3. Abra Dashboard.
4. Abra Conversas.
5. Envie uma mensagem para o WhatsApp conectado.
6. Confirme que a mensagem aparece na aba Conversas.
7. Confirme que a IA responde.
8. Abra Kanban.
9. Confirme que o card aparece no Kanban do tenant.
10. Envie uma mensagem pedindo atendente humano.
11. Confirme que o card vai para Aguardando humano ou Conversas com humanos,
    conforme a configuracao atual do frontend.
12. Responda manualmente pela interface.
13. Confirme que a resposta chega no WhatsApp.

select

  tm.email,

  t.slug,
  ts.settings->>'ai_enabled' as ai_enabled,
  ts.settings->>'ai_provider' as ai_provider,

  a.provider,
  a.model,
  pv.version,
  pv.active

join public.tenants t on t.id = a.tenant_id

  kc.automation_key

join public.tenants t on t.id = kb.tenant_id
where t.slug = 'universo_prata'
  and kb.is_default = true
order by kc.position;


8. LIMITACOES IMPORTANTES NO ESTADO ATUAL
-----------------------------------------

O cadastro acima deixa o cliente pronto para:

- login na interface;
- isolamento por tenant;
- WhatsApp conectado pela Evolution;
- prompt especifico por cliente;
- IA ativa via Gemini;
- visualizacao das conversas;
- resposta manual pela interface;
- Kanban customizado visualmente por cliente.

Ponto importante:

A interface ja carrega colunas customizadas por tenant, mas a movimentacao
automatica fina do Kanban ainda depende das chaves reconhecidas pelo frontend
e pelo workflow.

Hoje, as chaves mais seguras para automacao sao:

- conversas_ia
- conversas_andamento
- aguardando_humano
- com_humano
- verificar_sinal
- agendamentos
- finalizadas
- conversas_abandonadas

No exemplo Universo Prata, algumas colunas comerciais usam chaves futuras:

- produtos_apresentados
- interesse_compra
- aguardando_finalizacao

Essas colunas aparecem no Kanban, mas a movimentacao automatica para elas pode
exigir ajuste posterior no frontend/workflow para classificar etapas comerciais
com mais precisao.

Para teste inicial do novo WhatsApp, isso nao bloqueia o cadastro.
Para entregar o Kanban comercial perfeito da Universo Prata, o proximo passo
tecnico e adicionar classificacao estruturada de etapa comercial no workflow
e mapear essas etapas no frontend.
